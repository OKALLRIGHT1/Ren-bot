# 运行健康中心与 Rust 屏幕事件设计

## 目标

在不改变现有消息协议和用户数据格式的前提下：

1. 保留 Rust/Tauri 活动事件消费、工作统计、主动文本互动、久坐提醒和日记数据。
2. 彻底关闭屏幕事件触发的 Python 截图、视觉识别和本地前台窗口探测；QQ 图片识别等非屏幕视觉能力不受影响。
3. 提高 Live2D WebSocket 的断线恢复能力。
4. 避免限流模型被持续重复请求，并让降级原因可观测。
5. 建立可扩展的全局运行健康中心，统一提供脱敏状态快照。
6. 限制控制台日志体积，并让仓库测试入口开箱可用。

依赖库升级不在本次范围内。外置增强版前端的界面改造也不在本仓库范围内；本次提供稳定的结构化状态接口供它消费。

## 核心约束

运行健康中心只负责观测，不负责业务决策。

- 业务组件在完成自己的判断后上报状态。
- 聊天、模型路由、Rust 事件处理、连接重试不能依赖健康中心返回值才能继续。
- 健康中心写入失败不得改变业务结果。
- 模型冷却由模型路由层持有和执行，健康中心只展示冷却快照。
- 状态必须脱敏，不保存密钥、完整请求、用户对话、窗口标题或模型原始响应。

这避免健康中心成为新的单点故障或第二套业务状态源。

## 总体架构

新增 `services/runtime_health.py`，提供进程内、线程安全的 `RuntimeHealthCenter`。应用启动时创建一个实例，并通过轻量访问入口提供给函数式模块；组件只调用 `report()`、`clear()` 或 `snapshot()`。

健康记录至少包含：

- `component`：稳定组件标识，例如 `live2d_ws`、`rust_activity`、`model:<id>`、`qq_gateway`。
- `state`：`healthy`、`degraded`、`reconnecting`、`cooldown`、`offline` 或 `disabled`。
- `summary`：适合直接显示的短文本。
- `updated_at`：最后更新时间。
- `details`：脱敏结构化字段，例如重连次数、冷却截止时间、最后成功时间。
- `stale_after_seconds`：可选的新鲜度阈值；快照阶段计算 `stale`，不由调用者重复实现。

健康中心使用锁保护内存映射，不写数据库，不主动访问网络，不启动后台线程。`/runtime/status` 聚合健康快照和现有工作会话数据。

## Rust 屏幕事件边界

Python `ScreenSensor` 继续存在，但职责收窄为 Rust 活动事件消费者和统计器：

- 保留 `/activity-ingest`。
- 保留事件去重、前台应用切换处理、持续时间统计、工作会话、久坐提醒、文本主动互动和日记报告。
- 屏幕主动互动固定使用纯文本路径，`use_vision` 永远为 `False`。
- 删除屏幕事件中的概率视觉升级、截图调用和 `sensor_vision_*` 调用入口。
- 删除为校验屏幕事件而调用 Python 本地前台窗口 API 的逻辑，直接使用 Rust 事件携带的应用与标题。
- 保留 `modules/vision/capture.py` 给 QQ 图片或用户明确图片任务使用；不做全局视觉功能删除。
- Rust 活动源新鲜时上报 `healthy`，超过阈值时上报 `degraded`。仅在健康状态发生变化时写警告，避免每分钟刷屏。恢复时上报 `healthy` 并记录一次恢复日志。

## Live2D WebSocket 恢复

连接池继续作为唯一连接管理入口：

- 建连超时和手动 ping 超时统一提高到 5 秒。
- 初次失败后按 1、2、4、8、最高 15 秒指数退避，并加入小幅随机抖动。
- 成功连接或成功 ping 后清空连续失败次数和下一次重试时间。
- 连接状态变为 `reconnecting`、`offline` 或 `healthy` 时上报健康中心。
- 健康详情只包含主机标识、连续失败次数、下一次重试时间、最后成功时间和脱敏错误类别。
- 保留现有 WebSocket 消息格式和连接池最大寿命。

调用方在退避窗口内收到明确的连接暂不可用异常，不创建额外并发连接。

## 模型限流冷却

模型路由层维护线程安全的进程内冷却表，键为模型配置标识：

- 识别 HTTP 429、`model_cooldown`、`rate limit` 和结构化 `reset_seconds`。
- 有明确重置时间时使用服务端时间；没有时默认冷却 60 秒，最长不超过 15 分钟。
- 路由候选遍历时跳过仍在冷却的模型，继续尝试后备模型。
- 模型成功调用后清除其冷却和错误状态。
- 所有候选都不可用时沿用现有错误或原始回复降级路径，不伪造成功。
- 冷却开始、跳过和恢复时更新 `model:<id>` 健康记录。
- 健康状态不包含 API Key、Base URL 查询参数、提示词或响应正文。

流式与非流式调用共享同一个冷却表，避免两条路径重复轰击同一模型。

## 运行状态接口

扩展现有 `GET /runtime/status`，返回：

- `overall`：根据各组件状态计算的 `healthy`、`degraded` 或 `offline`。
- `components`：健康中心的脱敏组件快照。
- `screen_sensor`：Rust-only 模式、绑定状态、活动源是否过期。
- `work_session`：现有工作会话。
- `latest_rust_event`：现有最后事件摘要。

应用初始化时为可发现组件上报初始状态：Live2D WebSocket、Rust 活动源、模型路由、QQ 网关、TTS、ASR、插件管理器。无法可靠判断的组件使用 `disabled` 或 `offline`，不通过探测外部服务来伪造健康。

旧字段继续保留，避免已有增强版前端解析失败。新增字段只做向后兼容扩展。

## 控制台日志轮转

`core/console_capture.py` 使用一个共享、线程安全的轮转写入器：

- `console.log` 单文件上限 10 MB，保留 5 个备份。
- stdout 和 stderr 共享同一写入器，避免两个文件句柄同时轮转。
- 继续镜像到原始 stdout/stderr。
- 安装操作保持幂等。
- 日志文件异常时保留原始控制台输出，不让日志故障阻断应用启动。

## 测试入口

- 新增 `pytest.ini`，设置 `testpaths = tests`。
- `package.json` 的 `npm test` 调用 `python -m pytest -q`。
- 不改动 `data/` 内第三方测试样本。

## 测试策略

严格按测试先行实现：

1. 健康中心：线程安全写入、脱敏快照、新鲜度和 overall 聚合。
2. Rust-only 屏幕路径：事件仍触发统计和纯文本互动，但截图函数与视觉模型永不调用；本地前台窗口函数永不调用。
3. WebSocket：5 秒超时、失败退避、成功复位、状态上报。
4. 模型路由：429 建立冷却、冷却候选跳过、后备模型继续、成功清除、流式与非流式共享。
5. 运行状态：保留旧字段并加入脱敏组件状态。
6. 控制台日志：达到阈值后轮转、stdout/stderr 共享写入器、重复安装幂等。
7. 测试入口：直接执行 `python -m pytest -q` 不再收集 `data/`，`npm test` 返回同一测试结果。

最终验证顺序：目标测试、完整 `python -m pytest -q`、`npm test`、`git diff --check`。

## 完成标准

- Rust 活动事件仍能驱动统计、主动文本互动、久坐提醒和日记数据。
- 屏幕事件不会调用 Python 截图、视觉模型或本地窗口探测。
- WebSocket 失败不会形成高频重连，并能在恢复后清零失败状态。
- 限流模型在冷却期内被跳过，备用模型仍可使用。
- `/runtime/status` 能解释活动源过期、连接重试和模型冷却等用户可感知问题。
- `console.log` 不再无限增长。
- 两个标准测试入口均通过，且不误收集第三方样本。
