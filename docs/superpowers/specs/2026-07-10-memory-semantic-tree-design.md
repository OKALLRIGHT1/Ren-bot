# 记忆核心语义分类树设计

## 目标

把记忆核心从面向实现的 `fact / preference / profile / rule` 平铺列表，改为面向用户理解的语义档案树。相同主题的内容集中展示，例如喜欢的音乐放在“喜欢 / 音乐”，不喜欢的内容放在“不喜欢”，回复习惯放在“互动与回复规则”。

本次只调整记忆管理界面的组织方式和分类元数据，不改变 Memory Core 的召回、画像、学习、证据和权限逻辑。

## 界面结构

记忆核心页改为左右两区：

- 左侧为固定宽度语义分类树，显示分类名称和记录数量。
- 右侧上方为当前分类内的搜索、人物范围、状态筛选和刷新。
- 右侧中间为记录列表，只显示当前分类的记录。
- 右侧下方为选中记录编辑区，保留内容、人物、会话、置信度、重要度、人工锁定、保存、归档和删除。
- `kind`、稳定键、来源和记录 ID 保留，但放入“高级信息”，不再作为主要导航。
- 日记继续使用独立日记窗口，不进入“经历与事件”分类。
- Transcript 和旧向量库仍为独立页面，不进入语义分类树。

## 分类树

第一版固定分类如下：

- 全部记忆
- 称呼与身份
- 喜欢
  - 音乐
  - 动漫与角色
  - 游戏
  - 食物
  - 绘画与审美
  - 其他
- 不喜欢
- 习惯
- 近期状态
- 互动与回复规则
- 经历与事件
- 待办与承诺
- 未分类

空分类可以保留但显示数量 `0`，避免分类树随数据变化跳动。

## 自动分类

自动分类采用确定性规则，不调用 LLM。优先级从高到低：

1. `metadata.category_override` 手动覆盖。
2. 稳定键前缀。
3. `kind`、来源类型和少量明确标签。
4. 无法确定时进入“未分类”。

主要映射：

| 稳定键或类型 | 语义分类 |
|---|---|
| `preferred_address`、`name`、`identity_*`、`role:*` | 称呼与身份 |
| `likes.music.*` | 喜欢 / 音乐 |
| `likes.games.*` | 喜欢 / 游戏 |
| `likes.food.*` | 喜欢 / 食物 |
| `likes.anime.*`、`likes.character.*` | 喜欢 / 动漫与角色 |
| `likes.art.*`、明确绘画审美项 | 喜欢 / 绘画与审美 |
| `likes.*` | 喜欢 / 其他 |
| `dislikes.*` | 不喜欢 |
| `habit.*`、`notes.*` 中明确习惯项 | 习惯 |
| `status.*` | 近期状态 |
| `reply.*`、`interaction_*`、`kind=rule` | 互动与回复规则 |
| `kind=episode` 且不是日记 | 经历与事件 |
| `user_task`、承诺或待办来源 | 待办与承诺 |
| 其他 | 未分类 |

“绘画与审美”等无法只靠 key 判断的旧 `likes.general.*`，第一版使用有限、可测试的内容词表归类；不做开放式关键词猜测。

## 手动调整

编辑区增加“分类”下拉框和“恢复自动分类”命令。

- 手动调整写入 `memory_records.metadata_json.category_override`。
- 覆盖值使用稳定分类 ID，例如 `likes.music`，不存中文显示文本。
- 恢复自动分类时删除 `category_override`。
- 不新增 `category` 数据库列，避免分类列与稳定键成为两个并行事实源。
- 保存其他字段时必须保留现有 metadata，不得覆盖来源、时间或证据信息。

## 组件边界

- 新增纯函数分类模块，负责分类 ID、显示名称、父子关系和记录分类，不依赖 Qt。
- `MemoryCoreRepository` 只增加受控的 metadata 更新能力，不负责界面分类规则。
- `MemoryEditorDialog` 负责构建分类树、根据分类过滤记录和提交手动覆盖。
- 分类模块可以被未来的导出、审计或其他 GUI 复用。

## 错误与兼容

- metadata 缺失、格式错误或覆盖值未知时回退自动分类。
- 未知稳定键进入“未分类”，不静默归入“喜欢 / 其他”。
- 旧记录无需迁移，首次打开即可按现有 key 自动分组。
- 手动覆盖只影响 GUI 组织，不改变记忆召回和画像生成。
- 人物隔离、人工锁定和日记过滤保持现有行为。

## 测试与验收

- `likes.music.*`、`likes.games.*`、`likes.food.*` 分别进入正确子分类。
- `dislikes.*`、`status.*`、`reply.*` 和 `kind=rule` 进入正确分类。
- 日记记录不进入“经历与事件”。
- 未知 key 进入“未分类”。
- 手动覆盖保存后立即移动到目标分类，重启后仍有效。
- 恢复自动分类后回到规则计算结果。
- 更新分类不得丢失其他 metadata。
- 切换人物、状态和分类时列表与数量一致。
- GUI 在常见窗口宽度下不出现文字重叠，左侧树保持稳定宽度。
- 完整测试、编译检查和离屏截图验证通过。
