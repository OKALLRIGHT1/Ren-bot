# 嵌入式助手实施方案

这份文档是当前 `live2d-llm` 项目的精简版落地方案，目标是把桌面助手逐步升级成有独立终端、基础感知、可扩展外设的“实体化助手”。

当前状态：这是长期路线文档，不是当前主程序必须依赖的部署步骤。现在最稳的是“主电脑继续跑主脑，ESP32 先做感知节点，本地/小终端逐步接显示”。

核心原则只有三条：

- `主电脑 = 主脑`
- `Linux 小板 / 小终端 = 显示与轻服务`
- `ESP32 = 传感器与控制节点`

不建议一开始把主脑、记忆、知识库、QQ、TTS 全搬到板子上。

---

## 1. 总体推荐架构

### 主脑层（继续在主电脑）

保留在电脑：

- LLM 编排
- 记忆系统
- 知识库
- QQ / NapCat 对接
- 角色、服装、TTS 调度
- Live2D 状态控制

### 终端层（可独立出来）

可以逐步拆出的内容：

- 独立屏幕显示 Live2D
- 字幕 / 状态页
- 轻量 Web 页面
- 轻量反代（例如 Exa 反代）

### 感知层（最适合先做）

由 ESP32 承担：

- PIR 人体红外
- 按钮
- NFC / RFID
- 距离传感器
- 光照 / 温湿度

### 通信层

推荐：

- `MQTT`：设备事件和控制总线
- `WebSocket`：显示终端同步
- `HTTP`：管理接口与轻服务

---

## 2. 低预算推荐路线

如果你当前预算有限，不建议先买第二台服务机。

最推荐路线：

1. 主电脑继续跑全部核心逻辑
2. 先上 `ESP32 + PIR + 按钮`
3. 有条件再加一块终端板负责显示
4. GPT-SoVITS 暂时留在主电脑

这一阶段重点不是“全屋智能”，而是先做出：

- 她知道你来了
- 她能主动互动
- 她能从独立终端出现

---

## 3. 哪些服务适合搬离主电脑

### 适合优先迁移

- `GPT-SoVITS`：最吃资源，后期可独立服务化
- `NapCat`：可独立，但不建议放低配板子
- `Exa 反代`：轻服务，最适合先迁到轻设备
- `MQTT broker`：很轻，迁不迁都可以

### 不建议优先迁移

- 主脑
- 记忆系统
- 知识库主逻辑
- 复杂视觉识别

---

## 4. 设备选型建议

### ESP32

适合：

- PIR
- 按钮
- NFC
- 距离传感器
- 灯控 / 继电器
- MQTT 上报

不适合：

- NapCat
- 反代主服务
- 人脸识别主逻辑
- TTS / LLM

### Orange Pi Zero 3 / Radxa Zero 3W / 树莓派 Zero 2 W

统一定位：

- 轻终端
- 轻服务
- 显示页面
- 轻量 Exa 反代

不适合：

- GPT-SoVITS
- NapCat 主服务
- 主脑
- 重视觉识别

### Orange Pi 3B

比 Zero 系列更稳，更适合：

- 同时跑显示、轻页面、轻服务
- 作为小型桌面终端

一句话：

- `预算紧 -> Zero 3 / Radxa Zero 3W`
- `想更稳 -> Orange Pi 3B`

### 旧 x86 小主机 / 旧笔记本

如果你的目标是“把服务迁出去”，这类通常比树莓派更合适：

- 跑 NapCat
- 跑 GPT-SoVITS
- 跑 Nginx / Caddy
- 跑 Exa 反代

## 6. ESP32 第一阶段模块清单

### 必需

- ESP32 开发板 1 块
- PIR 红外 1 个
- 按钮 1 个
- 杜邦线若干
- USB 线 1 根

### 可选

- 面包板
- LED 状态灯
- 距离传感器（第二阶段）

### 第一阶段目标

先只完成：

1. 按钮按下 -> 向主脑发 MQTT
2. PIR 检测到人 -> 向主脑发 MQTT
3. 主脑收到消息 -> 触发语音/提醒/角色状态变化

---

## 7. ESP32 第一阶段接线建议

### PIR

- `VCC -> 5V`
- `GND -> GND`
- `OUT -> GPIO 27`

### 按钮

- 一端 `GPIO 26`
- 一端 `GND`
- 软件启用内部上拉

### LED（可选）

- `GPIO 2 -> LED 正极（串限流电阻）`
- `GND -> LED 负极`

作用：

- 联网成功闪烁
- 收到主脑确认闪烁

---

## 8. MQTT Topic 设计（第一阶段）

统一前缀建议：

```text
suzu/
```

### 设备上报

#### 在线状态

```text
suzu/device/presence-button-node/status
```

示例：

```json
{"online": true, "ip": "192.168.1.50", "ts": 1711111111}
```

#### PIR

```text
suzu/sensor/pir
```

示例：

```json
{"node": "presence-button-node", "value": 1, "ts": 1711111111}
```

约定：

- `value=1` 有人
- `value=0` 空闲

#### 按钮

```text
suzu/device/button
```

示例：

```json
{"node":"presence-button-node","button":"speak","action":"press","ts":1711111111}
```

### 主脑下发（预留）

```text
suzu/action/device/presence-button-node
```

示例：

```json
{"led":"blink","duration_ms":500}
```

### 第二阶段预留

```text
suzu/sensor/distance
suzu/device/nfc
suzu/presence/phone
suzu/action/switch_role
suzu/action/speak
suzu/display/eink/state
```

---

## 9. 主脑第一阶段建议响应逻辑

### PIR 触发后

- 角色状态切 active
- 可选播一句欢迎语

### 按钮触发后

- 说一句固定介绍
- 或播报提醒
- 或切角色

建议先做最简单版本，不要一上来做复杂设备编排。

## 10. ESP32 墨水屏状态面板建议

这个方向是可行的，而且很适合 ESP32。

定位建议：

- `低功耗状态屏`
- 不是动态 Live2D 屏

适合显示：

- 当前角色名
- 当前情绪
- 当前状态
- 简短一句字幕/提醒

推荐布局：

1. 第一行：角色名
2. 第二行：情绪图标
3. 第三行：状态文案

例如：

```text
丰川祥子
[平静]
欢迎回来
```

推荐主题：

```text
suzu/display/eink/state
```

示例：

```json
{
  "role": "丰川祥子",
  "emotion": "calm",
  "status": "welcome_back",
  "text": "欢迎回来"
}
```

## 12. 能不能让板子顺便跑 Exa 反代 / NapCat

### Exa 反代

可以放轻板上，推荐程度：中。

适合：

- Orange Pi Zero 3
- Radxa Zero 3W
- Orange Pi 3B

### NapCat

不建议现在放到 Zero 级板子上。

原因：

- 你还是新手阶段
- NapCat 不属于特别省心的轻服务
- 板子余量有限

建议：

- 先留主电脑
- 或后续迁到旧 x86 小主机

---

## 13. 如果你是新手，应该怎么开始

最推荐路线：

1. 先学 ESP32 + MQTT
2. 先把按钮和 PIR 跑通
3. 再考虑加显示终端
4. 最后再考虑迁服务

不要一开始就做：

- 板子上跑很多服务
- 视觉识别
- NapCat 迁移
- GPT-SoVITS 迁移

你现在最稳的路线仍然是：

- `主电脑做主脑`
- `ESP32 做感知`
- `板子做显示/轻服务`

这条路最省钱，也最不容易把自己劝退。

## 14. 你当前阶段可直接采购的清单

如果你现在准备先买：

- 小状态屏
- ESP32
- 按钮
- 传感器

那我建议你先不要追求“功能全”，而是按“能最快搭起来、最不容易踩坑”的标准买。

### 14.1 核心推荐清单（最稳妥）

#### 1. ESP32 开发板 x 1

建议关键词：

- `ESP32 DevKit`
- `ESP32-WROOM-32`

原因：

- 最常见
- 教程最多
- GPIO 足够
- Wi-Fi 稳定

#### 2. 小状态屏 x 1

推荐方向：

- `ESP32 可直连的小液晶屏`

建议规格：

- `1.54 寸 ~ 2.8 寸`
- `SPI 接口`

推荐用途：

- 显示当前角色
- 显示当前情绪
- 显示状态文字
- 显示提醒数量

不建议现在就买：

- 5 寸 HDMI 屏给 ESP32 带

因为：

- ESP32 不适合带 HDMI 大屏
- 更适合带小型 SPI 状态屏

#### 3. PIR 人体红外传感器 x 1

用途：

- 检测你是否靠近桌面
- 触发“欢迎回来”“切 active 状态”

#### 4. 按钮模块 x 1

用途：

- 一键触发说话
- 一键切角色
- 一键播提醒

#### 5. 杜邦线 + 面包板

用途：

- 初期接线最方便
- 减少焊接门槛

### 14.2 可选补充件

#### LED 状态灯 x 1

作用：

- 联网成功亮起
- 收到主脑事件闪烁
- 便于调试

#### 距离传感器 x 1

作用：

- 比 PIR 更细地判断你是否靠近桌面
- 可作为第二阶段升级件

#### NFC 模块 x 1

作用：

- 后面可以做刷卡切角色
- 很有“实体助手”的仪式感

## 15. 小状态屏推荐方向

### 最推荐：小液晶 SPI 屏

原因：

- 比墨水屏便宜
- 比 OLED 信息量更大
- 刷新比墨水屏快
- 比 HDMI 屏更适合 ESP32

推荐用途：

- 显示角色名
- 显示情绪图标
- 显示状态词
- 显示提醒状态

推荐大小：

- `1.54 寸`：紧凑，适合简单状态
- `2.4 寸 / 2.8 寸`：更实用，我更推荐

### 墨水屏什么时候买

如果你以后更追求：

- 低功耗
- 常亮状态牌
- 安静、不刺眼的桌面装置感

再考虑墨水屏。

但当前阶段，`液晶状态屏` 更适合你。

## 16. 推荐显示内容布局

第一阶段状态屏建议只显示这些：

## 19. ESP32 型号选择建议

如果你准备买 ESP32，当前项目最推荐：

- `ESP32-S3 N16R8（焊好排针）`

原因：

- `16MB Flash + 8MB PSRAM` 余量更大
- 带小液晶状态屏更从容
- 后续继续加 NFC / 距离传感器 / 更复杂状态页也更稳
- 焊好排针更适合新手，接面包板和杜邦线最省事

如果预算更紧，也可以退一步选：

- `ESP32-WROOM-32 DevKit（焊好排针）`

但如果已经买了 `ESP32-S3 N16R8`，那就是当前很不错的选择。

## 20. 你接下来还需要买什么

既然你已经买了 `ESP32-S3 N16R8（焊好排针）`，那下一批建议直接围绕“第一阶段能跑起来”来买。

### 必买

1. `PIR 人体红外传感器`
- 用途：检测你是否靠近桌面
- 建议：选最常见的模块化版本，三引脚（VCC/GND/OUT）即可

2. `按钮模块`
- 用途：一键触发说话 / 提醒 / 切角色
- 建议：先买最普通的单按键模块即可

3. `面包板`
- 用途：前期免焊接搭建
- 建议：买标准中号面包板就够

4. `杜邦线`
- 用途：接 ESP32、PIR、按钮和屏幕
- 建议：公对母、公对公都备一点

### 强烈推荐

5. `小液晶 SPI 状态屏`
- 用途：显示角色名、情绪、状态、提醒
- 推荐尺寸：
  - `2.4 寸`
  - `2.8 寸`
- 推荐理由：
  - 比墨水屏便宜
  - 刷新快
  - 比 1.x 寸屏更实用

### 第二阶段再买

6. `距离传感器`
- 用途：更细地判断你是否靠近桌面

7. `NFC 模块`
- 用途：刷卡切角色，仪式感更强

8. `LED 状态灯`
- 用途：联网状态 / 收到事件反馈

---

## 21. 小状态屏怎么选

你现在这块 ESP32 不适合带 HDMI 大屏，建议选：

- `SPI 接口液晶屏`

推荐优先级：

1. `2.4 寸 SPI 液晶屏`
2. `2.8 寸 SPI 液晶屏`
3. `1.54 / 1.8 寸小屏`（太小，只建议极简状态）

用途建议：

- 第一行：角色名
- 第二行：情绪图标
- 第三行：状态文字

例如：

```text
丰川祥子
[平静]
欢迎回来
```

不建议你现在就买：

- 墨水屏（贵、慢）
- HDMI 5 寸屏（ESP32 不适合带）
